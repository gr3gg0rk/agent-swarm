    - Constructor: taskId, agentId, mqttClient (MqttClientMinimal), updateInterval (number, default 30000ms)
    - Private properties: updateInterval, progressInterval?, lastProgress (number, default 0), startTime (number, Date.now())

    - start(initialProgress: number = 0): void
      * Sets lastProgress = initialProgress
      * Starts setInterval calling publish(this.lastProgress) every updateInterval ms
      * Stores interval ID in progressInterval

    - update(progress: number, message?: string): void
      * Calculates progressChange = Math.abs(progress - this.lastProgress)
      * If progressChange >= 10: publishes immediately with this.lastProgress = progress
      * Otherwise: waits for next interval (no-op)

    - stop(): void
      * Clears interval if progressInterval exists
      * Sets progressInterval = undefined

    - publish(progress: number, message?: string): private void
      * Creates MessageEnvelope with:
        - messageId: uuidv4()
        - idempotencyKey: uuidv4()
        - from: this.agentId
        - type: 'progress'
        - timestamp: Date.now()
        - payload: { taskId, agentId, progress, message, timestamp }
        - qos: 0 (fire-and-forget per COMM-07)
        - retain: false
      * Publishes to Topics.taskProgress(this.agentId)
      * Serializes with JSON.stringify()

    Follow CONTEXT.md decision: "Periodic progress updates: workers send updates at fixed intervals (every 10% or 30s)"
    Follow CONTEXT.md decision: "Exact progress update interval (10% vs 30s vs other)" - use both: publish immediately on 10% change, otherwise every 30s
    Follow RESEARCH.md pattern: ProgressReporter with setInterval + 10% threshold check

    DO NOT create task execution logic - just the progress reporting mechanism.

  <name>Implement WorkerTaskExecutor for task execution with timeout and result publishing</name>
  <files>
    packages/coordination/src/delegation/worker.ts
  </files>
  <action>
    Create packages/coordination/src/delegation/worker.ts with WorkerTaskExecutor class:
    - Constructor: agentId (string), mqttClient (MqttClientMinimal), taskQueue (TaskQueue), timeoutMonitor (TimeoutMonitor)
    - Private properties: agentId, mqttClient, taskQueue, timeoutMonitor, activeTasks (Map<string, ProgressReporter>)

    - setupCommandHandler(): private void (call in constructor)
      * Subscribes to Topics.workerCommands(this.agentId) or Topics.taskCommand(this.agentId)
      * Sets up message handler calling handleCommand()

    - private async handleCommand(message: Buffer): Promise<void>
      * Parses message as MessageEnvelope
      * If envelope.type === 'task': calls executeTask()
      * If envelope.type === 'cancel': calls handleCancellation()

    - private async executeTask(command: TaskCommandPayload): Promise<void>
      * Extracts taskId, payload, timeoutMs, maxRetries from command
      * Updates task status to 'in_progress' in TaskQueue
      * Creates ProgressReporter with taskId, agentId, mqttClient
      * Calls progressReporter.start(0) and stores in activeTasks map
      * Starts timeout monitoring: timeoutMonitor.startTimeout(taskId, timeoutMs, 0, maxRetries, handleTimeout callback)
      * Try:
        - Calls doWork(payload, onProgress callback)
        - onProgress: calls progressReporter.update(), updates TaskQueue with lastProgressAt
        - On success: calls sendResult() with success: true, result, executionTime
        - Cleanup: timeoutMonitor.cancelTimeout(taskId), progressReporter.stop(), activeTasks.delete(taskId)
        - Updates task status to 'completed' in TaskQueue
      * Catch error:
        - Classifies error with classifyError()
        - Calls sendResult() with success: false, error type, message, executionTime
        - Cleanup: timeoutMonitor.cancelTimeout(taskId), progressReporter.stop(), activeTasks.delete(taskId)
        - Updates task status to 'failed' in TaskQueue

    - private async handleTimeout(taskId: string, retryCount: number): Promise<void>
      * Gets task from TaskQueue
      * Returns early if task.status !== 'in_progress'
      * If retryCount <= (task.maxRetries || 3):
        - Updates task status to 'pending' in TaskQueue for re-dispatch
        - Logs retry message
      * Else (exhausted):
        - Calls notifyMinerva() with task_failed event

    - private async sendResult(taskId: string, result: TaskResultPayload): Promise<void>
      * Creates MessageEnvelope with:
        - messageId: uuidv4()
        - idempotencyKey: uuidv4()
        - from: this.agentId
        - type: 'result'
        - timestamp: Date.now()
        - payload: { taskId, ...result }
        - qos: 1 (at-least-once per COMM-06)
        - retain: false
      * Publishes to Topics.taskResult(this.agentId)
      * Serializes with JSON.stringify(), use MessagePack if payload size > 1KB

    - private async handleCancellation(cancelPayload: TaskCancelPayload): Promise<void>
      * Gets taskId from payload
      * Gets ProgressReporter from activeTasks map
      * If exists: calls stop(), deletes from map
      * Cancels timeout: timeoutMonitor.cancelTimeout(taskId)
      * Updates task status to 'cancelled' in TaskQueue
      * Publishes acknowledgment to Topics.taskResult(this.agentId)

    - protected async doWork(payload: unknown, onProgress: (progress: number, message?: string) => void): Promise<unknown>
      * Throws Error('doWork must be implemented by agent subclass')
      * This is abstract - each agent type implements their own work logic

    Follow CONTEXT.md decision: "Multi-task agents: workers can handle multiple tasks concurrently up to declared capacity"
    Follow CONTEXT.md decision: "Re-queue at front: rejected tasks go to front of queue for immediate re-dispatch"
    Follow RESEARCH.md pattern: WorkerTaskExecutor with progress tracking and timeout monitoring

    DO NOT implement actual doWork() - that's agent-specific. DO NOT create Minerva notification system - that's a later concern.
  </action>
