  <files>

  <action>
    Create packages/coordination/src/delegation/timeout.ts with:

    - TimeoutMonitor class:
      * Private property: timeouts: Map<string, NodeJS.Timeout>
      * startTimeout(taskId: string, timeoutMs: number, retryCount: number, maxRetries: number, onTimeout: (taskId: string, retryCount: number) => void): void
        - Sets timeout for timeoutMs duration
        - On timeout: calculates exponential backoff with jitter
        - Base delay: Math.pow(2, retryCount) * 1000 (1s, 2s, 4s, 8s...)
        - Jitter: Math.random() * 1000 (up to 1s random)
        - Capped delay: Math.min(baseDelay + jitter, 30000) (max 30s)
        - If retryCount < maxRetries: schedules retry with delay
        - If retryCount >= maxRetries: calls onTimeout with retryCount + 1 to signal exhaustion
      * cancelTimeout(taskId: string): void - clears timeout and removes from map

    - classifyError(error: Error): 'transient' | 'permanent' function
      * Transient patterns: /timeout/i, /etimedout/i, /econnrefused/i, /enotfound/i, /econnreset/i, /network/i, /temporary/i
      * Permanent patterns: /einvalid/i, /epermission/i, /eauth/i, /validation/i, /not found/i, /unauthorized/i
      * Returns 'permanent' if permanent pattern matches
      * Returns 'transient' if transient pattern matches
      * Defaults to 'transient' for unknown errors

    Follow CONTEXT.md decision: "Auto-retry first: timed out tasks automatically retry with exponential backoff + jitter"
    Follow CONTEXT.md decision: "Default + override: 2-minute default timeout, task creator can override per-task"
    Follow RESEARCH.md pattern: Exponential backoff with capped jitter per AWS guidance

    DO NOT create actual retry logic - just the timeout mechanism. DO NOT integrate with TaskQueue - that's in the next plan.
