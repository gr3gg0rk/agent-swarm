<objective>
Implement incremental checkpointing system enabling agents to resume from last checkpoint after crash or restart. Uses hybrid storage: fast local JSON files every 60 seconds for quick recovery, synchronized to SQLite every 5 minutes and on shutdown for cross-machine recovery.

Purpose: Prevents work loss during agent crashes - critical for long-running tasks where restarting from scratch wastes significant time and resources.

Output: CheckpointManager with LocalFileStore and SQLiteSync, checkpoint types, extended database schema, resume validation logic.
</objective>

  <action>
    Create packages/coordination/src/checkpoint/manager.ts with CheckpointManager class:

    Constructor:
    - localStore: LocalFileStore
    - sqliteSync: SQLiteSync
    - syncIntervalMs: number (default: 300000 = 5 minutes)
    - lastCheckpointTime: Map<taskId, timestamp>
    - lastCheckpointState: Map<taskId, JSON string> for change detection
    - pendingSync: Set<checkpointId>

    Methods:
    1. async createCheckpoint(taskId: string, data: CheckpointData, options?: CreateCheckpointOptions): Promise<string>
       - Check if should checkpoint: options.force OR task.timeInvestedMs > 120000 OR task.checkpointWorthy
       - Skip if state unchanged (compare JSON with lastCheckpointState)
       - Skip if task is blocked, waiting, or idle (status check)
       - Generate checkpointId using uuidv4()
       - Write to localStore (async, non-blocking)
       - Add to pendingSync set
       - Update lastCheckpointTime and lastCheckpointState
       - Return checkpointId

    2. async loadCheckpoint(taskId: string): Promise<CheckpointData | null>
       - Try localStore.loadLatest(taskId) first (fast path)
       - Fallback to sqliteSync.loadLatest(taskId) if local returns null
       - Return null if neither has checkpoint

    3. async syncToDatabase(): Promise<void>
       - For each checkpointId in pendingSync:
         - Load from localStore
         - Save to sqliteSync
         - Remove from pendingSync
       - Log sync count

    4. startPeriodicSync(): void
       - setInterval every syncIntervalMs (5 minutes)
       - Call syncToDatabase()

    5. stopPeriodicSync(): void
       - Clear interval

    6. async syncBeforeShutdown(): Promise<void>
       - Call syncToDatabase() to flush pending checkpoints

    Pattern reference: Interval management similar to HeartbeatPublisher (02-02-SUMMARY.md), pending set similar to idempotency tracker (01-03-SUMMARY.md).

    Per CONTEXT.md locked decision: "60-second checkpoint interval when task state has changed (skip if unchanged)."
    Per CONTEXT.md locked decision: "Sync triggers: agent shutdown (graceful or crash) AND periodic 5-minute timer."
