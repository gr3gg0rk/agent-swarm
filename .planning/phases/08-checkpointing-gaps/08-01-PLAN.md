<objective>
Implement atomic checkpoint writes with CRC32 checksums to prevent corruption and enable early detection.

**Purpose:** Checkpoint corruption causes cascading failures when agents resume from bad state. CRC32 checksums validated on recovery catch corruption early, and atomic writes (temp file + rename) prevent partial writes from crashing the system.

**Output:** Checkpoint system with CRC32 checksums computed before write, validated on load, and atomic write pattern extended with checksum metadata.

Per 08-CONTEXT.md: Compute checksum on write (before fsync) and validate on load. Validate CRC32 on local files only (SQLite is less prone to corruption). Delete corrupted checkpoint after successful fallback.

Per 08-RESEARCH.md: Use `crc-32` library for checksums. Existing LocalFileStore already implements atomic write pattern (store.ts:80-102). Extension: Add CRC32 checksum to temp file content before rename.

</objective>
